LedgerLoop is a multi-source payment reconciliation and settlement engine. It normalises gateway, bank, and internal-ledger records, resolves them in four passes that each see only the previous pass's residue, and settles what is left with Decimal arithmetic. A model may recommend a match. Python decides, and an unresolved result is a valid result.

Derivation

Try

Four passes, each with less left to resolve than the last.

Every stage receives only the residue of the stage before it, so a match can never be overwritten and a settled bank row can never support a second match. The counts below are the current run's, not an illustration.

What the engine refuses to do

  • Consume a bank row twice

    Bank rows are claimed one-to-one. A split settlement that needs two credits takes both, and no other transaction is offered either of them again.

  • Read the answer key

    ground_truth.csv is evaluation-only. No matching module imports it, and the server opens no files at all.

  • Force a match to look complete

    Contradictory, ambiguous, or missing evidence is returned as unresolved with a reason, not absorbed into a confident result.

  • Let a review change a result

    Every endpoint is read-only. An AI review returns a read-only assessment of stored context; it cannot select rows, change status, or alter arithmetic.

The model recommends. Python decides.

Gemini is bounded to a recommendation with named candidate rows. Before that recommendation can affect any state, the application re-checks candidate identity, one-to-one availability, and the settlement arithmetic. AI participation is opt-in; with no API key the deterministic tiers, this console, and the Q&A all still work.

  1. 01
    Deterministic rules run first

    Tier 1 matches exact reference plus amount. Tier 2 applies a documented amount tolerance and a closed set of reference transforms. No provider is consulted for either.

  2. 02
    Only genuine ambiguity reaches the model

    Tier 3 handles linked refund, TDS, and description cases deterministically first, then asks Gemini to adjudicate a split settlement. The response is a recommendation, not a result.

  3. 03
    Python re-validates before accepting

    Candidate IDs must exist, must not be consumed by another match, and must satisfy the settlement identity. A rejected recommendation is counted, not silently dropped.

  4. 04
    A person closes the gap

    Weak evidence stays in the human-review queue with a reason and the rows to read. Retry and review actions are stateful: they require an actor header and an audit record.

Offline is a supported mode, not a degraded one

LEDGERLOOP_ENABLE_AI=1 is required for AI to join the pipeline. Without a key, an explicit retry returns 503 and keeps the transaction retryable rather than inventing an outcome.

Grounded answers only

The Q&A layer answers from completed results and returns citations. Financial questions resolve to the stored deterministic value; unsupported questions are reported as unsupported instead of being answered plausibly.

Stack, scale, and how to run it yourself.

The engine uses only the Python standard library. Flask and Gunicorn serve the read-only API and this console; SQLite persists run snapshots and audit records. There is no build step for the frontend and no background worker.
